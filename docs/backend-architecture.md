# further-api 后端实现与迁移

网关品牌固定为 **further-api**，程序直接运行本仓库的 Go 服务。账户、认证、安全验证、配置、订阅账本、请求执行、计费、任务、支付与系统维护的核心流程已重写并接入正式入口，使用明确的服务和事务边界。官方协议 DTO、标准格式编解码、第三方 SDK 和已有数据库结构保留兼容。重写范围不表示每一行代码均为新作，也不取消历史贡献或第三方许可。代码来源、许可证与作者归属见根目录法律文件；验证要求见本文末尾。

## 已实现的独立服务边界

- `main.go` 管理资源初始化回滚、监听端口、后台任务、流式请求排空与退出清理。
- `model/bootstrap.go` 在同一事务内初始化管理员、运行选项与完成标记，数据库写入失败时一并回滚；提交后才发布内存状态，管理员显示名称为中文。
- `service/auth_*`、`model/user_session*` 管理短期访问令牌、HttpOnly 刷新 Cookie、服务端会话撤销及一次性安全验证。权限由服务端用户状态确认。
- `relay/channel/furtherapi` 根据入站协议确定级联网关路径和认证头，复用各厂商的协议编解码实现。
- `relaykit/types/gateway_error.go` 把错误原因、公开消息、上游载荷和重试策略分开管理。重新包装错误时创建副本；替换公开提示不会破坏原因链，也不会继续向客户端返回原始上游消息。
- `controller/metadata_transport.go` 负责可配置模型目录拉取、超时取消、有限重试、大小限制和已验证内容的 ETag 缓存。
- `service/workspace_bootstrap.go` 是新的工作台读取服务，独立组装初始化状态、公开配置、当前账户 DTO 和可用用户组。前端通过一次启动请求获得这些数据。账户查询可随请求取消，用户组复用已读取的账户分组；凭据缺失与凭据无效分别处理，禁用用户不能取得账户数据。
- `service/workspace_options.go` 替换原设置读取处理器。共享读锁只覆盖配置快照，派生计费配置与 JSON 编码在释放锁后进行，选项按键排序。凭据名称统一过滤，配置状态用明确的布尔值暴露；返回值不共享运行中的可变对象。
- 登录、刷新、工作台启动和 `/api/user/self` 共用 `WorkspaceAccount` 明确字段 DTO。数据库模型新增字段不会自动进入响应，密码哈希、管理令牌与管理员备注不会被读取或输出。
- `model/account_commands.go`、`account_profile.go`、`account_balance.go` 使用明确输入及事务处理账户资料、偏好、角色和余额；设置补丁保留其他偏好，令牌配置修改保留验证期间的并发扣费。
- `model/channel_catalog.go` 同一事务更新渠道配置及能力索引，事务失败保留原有路由；创建输入与服务端计数器分离，删除已经不存在的渠道保持幂等并使代理缓存失效。
- 原订阅单体已撤下。`model/subscription_catalog.go`、`subscription_checkout.go`、`subscription_schedule.go`、`subscription_reservations.go`、`subscription_lookup.go` 和 `subscription_workspace.go` 分别承担套餐、订单、周期、预留和权益查询；现有表结构保持兼容。秒级周期离线补偿按时间差一次计算，预扣编号绑定账户，配置变更不会发布旧缓存快照。
- `relay/channel/api_request.go` 与 `relay/helper/stream_scanner.go` 统一取消、响应释放和流写入；错误响应到达前不提交成功流。`service/error.go`、`http.go` 和 `relay_error.go` 限制错误体、过滤响应头并控制重试。
- `service/funding_source.go`、`billing_lifecycle.go` 累计钱包预留、处理订阅预留和一次退款，退款后不能再次结算；补偿任务参与程序退出排空。
- `service/risk_assessment.go` 使用联表稳定分页、按请求窗口计算详情并传递请求取消，复核状态在事务中提交。
- `service/workspace_site_settings.go` 和 `/api/further/workspace/site-settings` 使用明确 DTO 读取站点配置，验证全部字段后一次事务保存站点地址及 Linux DO 凭据。密钥只写入，响应仅提供配置状态；空密钥保留已有值，开启登录前验证完整凭据。
- `model/gateway_option_*` 将设置处理拆成类型绑定、纯解析校验、请求 Context 事务和提交后的运行配置发布。失败不会提前修改运行配置；付款确认在同一事务重新检查站点所有者与有效登录会话。
- `service/business/oauth_*`、持久化 `AuthFlow`、`model/account_finance.go` 管理身份归属、一次性验证码、密码重置、账户与初始凭据创建、余额及收入账本。邮件验证码的消费与注册写入同事务，写入失败后仍可重试。
- `model/account_security_management.go` 在事务内检查操作者和目标账户的最新角色，再重置双因素认证、通行密钥或清除身份绑定。通行密钥、恢复码和安全证明使用请求 Context、会话版本与单次消费约束。
- `relaykit/relayconvert/conversion_execution.go` 与 `stream_execution.go` 使用独立执行流程，在转换前和各步骤之间检查取消。流结束事件只完成一次，用量快照不共享可变字段；协议转换异常不会把输入内容写入公开错误。
- `relay/protocol_*`、`service/usage_publication.go`、`task_observation.go` 和新的 MJ 执行管理协议调用、资金预留与一次发布。实时语音累计预留后统一结算，任务终态通过持久化比较并交换决定谁退款，删除令牌不会阻止应退资金到账。
- 渠道探测采用统一请求执行，余额刷新按游标分批并限制并发；模型目录和渠道能力在同一事务提交，并检查配置版本，避免覆盖并发修改。
- OpenAI/Azure、Claude、Gemini、AWS、Vertex 和原生文本厂商执行已采用独立路径。OpenAI 实时语音由两个只读网络工作线程和一个状态持有循环组成，退出关闭两端并收拢线程，重复完成事件不重复计费；音频和图像读写错误明确返回。

## 厂商执行与协议边界

厂商接入使用明确的请求正规化、地址构造、认证、响应解码和执行状态。渠道通过共享的协议函数和执行服务协作；每次尝试单独保存上传格式、模型映射、转换状态和用量。网络读取与客户端写入传递请求取消，响应资源在退出路径释放。

| 范围 | 当前执行方式与兼容边界 |
|---|---|
| OpenAI/Azure、Claude、Gemini | 请求策略、推理参数、上传、HTTP/SSE、Responses 与 Chat 双向桥接使用新流程。跨协议转换继续按官方 DTO 和能力规则执行，语义损耗通过诊断返回。 |
| AWS/Vertex | AWS 支持 Bearer 和 SigV4 凭据，原生 SDK 调用与响应事件由新的执行流程管理；Vertex 使用服务账户 JWT/OAuth、凭据指纹缓存、共享令牌获取和可取消的认证请求。模型、地区与云资源路径保留官方含义。 |
| 原生文本与向量厂商 | Baidu、Cloudflare、Cohere、Dify、Tencent、Ollama、智谱等的请求转换、HTTP/SSE/NDJSON 处理采用新的执行边界。Ollama 模型管理与 Gemini 模型目录查询也传递调用方取消；分页参数作为查询值编码。 |
| Coze/Replicate | 创建、轮询和结果查询采用明确终态与取消边界。轮询设有时间上限；Replicate 对查询地址、重定向和图片读取施加独立边界，避免凭据转发到未认可的目标。 |
| 即梦、MiniMax 与图像处理 | 签名使用真实请求方法和可重放请求体，图像数量以实际有效输出计算。MiniMax 的原生语音和图像处理已接入新执行；聚合音频尾帧不会再次输出已发送的音频。 |
| 实时语音、讯飞和 Volcengine | WebSocket 连接、取消、关闭和二进制帧解析由独立执行流程管理，状态变更和用量累计由明确的执行方负责。官方帧格式、鉴权算法和厂商 DTO 保留。 |
| 级联、自定义渠道与任务插件 | further-api 级联和自定义渠道直接选择协议路径并重置尝试状态。任务插件的单任务、批量查询把 Context 传到脚本调用与 HTTP；自定义重定向回调之后再次验证目标，独立客户端副本保留共享客户端配置。 |

AWS Nova 当前使用新的 SDK `InvokeModel` 缓冲调用。请求为流式时，收到完整上游结果后再输出对应协议的 SSE，包含文本、工具调用和用量；此路径不提供 Nova SDK 的增量响应事件。实际可用模型、媒体形式和工具能力仍取决于配置的上游服务。

官方协议结构、纯 DTO 投影、用量方言、模型目录、区域映射与成熟 SDK 是保留边界。厂商名称用于标识上游服务，产品品牌统一为 further-api。兼容旧数据、选项、Cookie 或接口标识的代码用于升级迁移；法律文件中的历史项目名称用于归属说明。

## 支付与订单

`GET /api/user/topup/info` 只返回当前完成真实配置的支付方式和公开固定产品。`POST /api/user/checkout` 接受支付渠道、金额、方式及可选产品 ID，返回服务器冻结的 `wallet_units`、`money`、`currency`、订单编号和结算地址。银行卡使用托管页面；签名表单使用返回的 POST 参数，不在浏览器计算签名。付款返回地址必须属于本站。

LDC 使用独立报价和签名付款协议。支付通知核验原始签名、订单绑定、币种及金额，账本以事务保证幂等。暂时无法结算的通知返回可重试结果；处理中通知不会误标为失败。商户凭据只写入，元数据不会返回密钥。

## 工作台启动契约

`GET /api/further/workspace/bootstrap` 返回 `{ "success": true, "data": { "schema_version": 1, "setup": {}, "status": {}, "authenticated": false, "user": null, "groups": {} } }`。

`setup` 提供 `status`、`root_init`、`database_type`；`status` 是公开配置白名单，保留登录、额度展示、导航与控制台公告所需字段。匿名请求的 `user` 为 `null`；携带有效面板访问令牌或管理访问令牌的请求仅返回令牌所属账户，忽略 `user_id` 等外部目标参数。无效、被撤销或被禁用的凭据返回认证错误，不降级为匿名成功。响应禁止缓存。

`groups` 的每一项为 `{ "ratio": 1, "desc": "说明" }`；自动分组的 `ratio` 使用 `"自动"`，保持现有选择器的数据契约。权限矩阵由服务端账户权限计算，账户 DTO 中不使用客户端声明的角色。

管理设置读取为每个隐藏的凭据提供 `<option-key>Configured` 状态，值为 `true` 或 `false` 字符串；不返回凭据本身。界面明确选择清除后才提交空值。固定品牌选项与站点 Logo 不能改成其他值。

功能深链接直接选择控制台文档，在当前文档内恢复导航地址。构建提前下载工作区脚本，独立功能按需载入。公开页面共享启动状态快照，不再另外读取相同的安装和品牌状态。

兼容的 `/api/setup`、`/api/status`、`/api/user/self` 与 `/api/option/` 仍可单独调用，但现在使用上述服务读取边界。启动服务不会把管理员设置选项列表混入公开数据。

聊天预设的默认配置、状态字段与设置实现已删除。启动迁移清除已持久化的 `Chats` 选项，设置接口返回 `410 FEATURE_REMOVED`，旧数据库读入时也不会重新发布这个配置。

## 持久化命名迁移

启动时先迁移历史业务表名，再创建或更新当前结构。旧表中的余额、福利领取记录、订阅策略和渠道策略随表一起保留；发现旧表和目标表同时存在时，程序停止迁移并明确报告冲突，不覆盖任一表。

订阅来源标识与历史选项键在事务中转换；已有新键优先。迁移可以重复执行。历史认证 Cookie 仅用于读取并轮换到当前 Cookie；响应不再写入旧会话提示。集群升级应先停旧节点、备份数据库，完成主节点迁移后再启动同版本节点。

## 模型资料源与任务插件

内置任务插件随程序发布。远程插件目录由管理员显式配置，默认列表为空。插件级联网关声明为 `upstreams: ["vendor", "gateway"]`，运行时的 `ctx.upstream.kind` 使用 `gateway`。数据库中自行安装的插件源码若显式使用历史网关标识，需要先更新插件后启用；程序不会擅自修改这些自定义源码及其校验哈希。

模型资料同步需要设置 `FURTHER_METADATA_BASE`，例如 `https://catalog.example.com/further`。中文目录读取 `/zh/models.json` 与 `/zh/vendors.json`，英文使用 `/en/`，日文使用 `/ja/`。内容支持 JSON 数组或 `{ "success": true, "data": [...] }`。未配置时不连接任何默认远程目录。

模型条目支持 `model_name`、`description`、`endpoints`、`icon`、`name_rule`、`status`、`tags`、`vendor_name`；厂商条目支持 `name`、`description`、`icon`、`status`。相关管理 API 的预览、差异选择和版本校验流程继续使用这些数据；当前管理页面通过统一模型配置维护模型和渠道。

## 验证与发布

本次重写阶段已执行厂商整包、`relay/helper` 和 `relay` 的回归，以及账户安全、配置事务、支付通知、订阅和资金预留、任务终态、实时语音退出等定向验证。这些记录对应执行时的源码与模拟上游，不能代替最终发布产物的验证。

发布前需在根目录执行 `go test ./...`，在独立 `relaykit/` 模块执行 `go test ./...`，并完成前端类型检查、测试和完整构建。实际浏览器应检查首页与控制台导航、节日配色、弹窗退场、滚动动画、刷新恢复、移动布局及法律入口；桌面安装包另在目标平台验收。真实上游、支付通知和数据库升级也应在目标部署环境核对。最终版本的整套测试和浏览器验收由发布流程记录，不以阶段结果作未执行项目的结论。
