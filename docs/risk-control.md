# 管理员风险识别

入口为管理员后台的风险识别页面。评分只提供审核线索；确认、观察、忽略等审核状态不会禁用用户或修改余额。

## 数据与窗口

分别计算最近 3 天和 7 天。每个用户最多计算最近 20,000 条事件，达到此上限时详情的 `evidence.sample_limited` 为 `true`，请求数与信号均指该样本。事件仅保存时间、状态、token 数量、流式标记及不可逆摘要，不保存请求正文、原始 IP 或提示词；管理员接口仅返回聚合证据。

后台每分钟以有限批次删除 7 天以前的事件，并清除已经离开各自窗口的评分。审核决定独立保存。采集队列有界，满载时丢弃事件并记录运行日志，避免风险分析阻塞网关请求。

## 计分

每项归一化为 0–100，综合分为加权平均。0–24 为低风险，25–49 为中风险，50–74 为高风险，75–100 为严重风险。

| 信号 | 权重 | 主要条件 |
| --- | ---: | --- |
| 定时规律 | 18% | 自动识别 1 分钟到 24 小时的固定间隔，容许 10% 抖动；至少 6 个匹配间隔、70% 匹配率、3 个 UTC+8 日期及 48 小时实际跨度 |
| 输入重复 | 16% | 至少 5 次相同签名且占样本 40%；没有签名时可使用至少 8 次、80% 一致的已知 token 数量，替代信号最高 60 分 |
| 多模型 | 10% | 滚动 15 分钟内请求至少 4 个不同模型 |
| 402 后续 | 12% | 明确额度耗尽后 24 小时内继续失败至少 3 次；兼容 New API 明确的用户或令牌额度不足错误；成功请求后重置 |
| 非流式 | 8% | 至少 20 次成功请求且非流式占比至少 70%，早期鉴权与路由失败不参与该分母 |
| 深夜 | 8% | UTC+8 00:00–08:00，滚动 1 小时内至少 20 次请求 |
| 渠道不可用后续 | 10% | 同一模型不可用后 1 小时内继续失败至少 3 次；该模型成功后重置 |
| 测活被拦截 | 12% | 已知输入 token 数量在 1–64 之间、命中测活关键词且请求失败 |
| 多 IP | 6% | 同一个 API token 出现至少 3 个不同 IP 摘要；缺少 token 身份时按用户聚合 |

## 接口

- `GET /api/risk/users?window=7d&page=1&page_size=20`：支持 `username`、`level`、`status`；`level=attention` 表示高风险或严重风险。
- `GET /api/risk/users/:id?window=3d`：获取最新评分及聚合证据。
- `PATCH /api/risk/users/:id/status`：JSON `status` 可取 `unreviewed`、`watching`、`confirmed`、`dismissed`。

以上接口均要求管理员身份，禁止缓存并施加查询或敏感操作限流。审核操作写入现有管理员审计记录。
